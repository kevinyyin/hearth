# Hearth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dispatcher tool that replays Hurricane Beryl over synthetic Harris County patients, surveys their buildings with a deep agent over CoStar, Vexcel and Matterport data, proposes refuges for dispatcher approval, and places a consent call followed by a text.

**Architecture:** One Python package (`hearth/`) with a FastAPI app (`api/`) and a Next.js map (`web/`). Lanes share only `hearth/contracts.py`, the SQLite document store, and the run files under `results/`; no lane imports another lane's modules except through those. The simulation is offline and writes files; the building agent and voice run live and write to the store.

**Tech Stack:** Python 3.12, uv, pydantic v2, numpy, pandas, FastAPI, pytest; `deepagents` 0.7.x on `langchain-anthropic`; Next.js, MapLibre GL; ElevenLabs Agents (custom model endpoint); Photon 2.0 Python client.

**Spec:** `docs/superpowers/specs/2026-11-13-hearth-design.md` (wins on conflict). Section numbers like "spec 4" refer to the team's `hearth-spec.md` v5, which is not in the repo.

## Global Constraints

- Every patient is synthetic: `synthetic: true` in data, the word "simulated" on every web view.
- No sentence that says help is coming (delivery, ride, ETA) is written by a model. Those come from `hearth/messaging/templates.py`, chosen by code, only after a job is `accepted`.
- No medical advice. Medical questions get the fixed hand-off template.
- A move is never messaged, called or dispatched before a dispatcher approves it.
- No reply is never treated as safe.
- Every simulation run takes a seed; same seed, same output bytes.
- Every default number lives in `config/assumptions.yaml` with a `source` and `confirmed` flag; never inline. Each run copies the file next to its results.
- Every profile field carries `value`, `source` (`costar`, `matterport`, `vexcel`, `default`) and `confidence` (0..1). A missing layer is listed in `layers_missing`; no field is filled without a source.
- Cached building results are labeled `cached: true` in the API and the UI.
- Model ids live in config: `claude-haiku-5-5` (interpreter, guard), `claude-sonnet-5-5` (building agent, vision). Every Anthropic client sends header `anthropic-workspace-id: $ANTHROPIC_WORKSPACE_ID`.
- Secrets only in `.env` (git-ignored). Never claim lives saved anywhere in copy.
- Lane ownership (do not edit outside your lane): M = `hearth/contracts.py`, `hearth/store.py`, `hearth/config.py`, `hearth/buildings/`, `api/`; S = other `hearth/*.py`, `hearth/sim/`, `scripts/`, `config/scenarios/`; V = `hearth/messaging/`, `evals/interpreter*`, `web/app/phone/`; W = the rest of `web/`. `config/assumptions.yaml` is shared and append-only: any lane may add keys, nobody edits another lane's keys. A change to `hearth/contracts.py` goes through lane M.

## Verified facts (from a throwaway test on Nov 13, `deepagents` 0.7.38)

- `from deepagents import create_deep_agent`; `from langchain.agents.middleware import TodoListMiddleware`; planning is off unless that middleware is passed.
- `ChatAnthropic(model=..., default_headers={"anthropic-workspace-id": ...})` works; without the header the key is rejected.
- `create_deep_agent` accepts `tools`, `system_prompt`, `middleware`, `subagents` (list of dicts with `name`, `description`, `system_prompt`, `tools`), `memory` (list of file paths), `backend`, `interrupt_on` (`{"tool_name": True}`), `checkpointer`.
- `agent.stream(input, config, stream_mode="updates", subgraphs=True)` yields `(namespace, update)` tuples; a non-empty namespace means a subagent. Tool calls are on `update[node]["messages"][i].tool_calls`. The approval pause arrives as the node key `"__interrupt__"`.
- Resume with `Command(resume={"decisions": [{"type": "approve"}]})` from `langgraph.types`.
- `agent.get_state(config).values` has `todos` (items with `content`, `status`) and `files` (path to content).
- Three fake-tool subagents plus plan, file writes and one approval took 22.7 seconds on `claude-haiku-5-5`.

## Review Focus

1. A building has no scan, or is not in CoStar: the survey still returns a profile with defaults, `layers_missing` set, and no crash. (Tasks 2, 4)
2. EAGLE-I glitches (readings near zero mid-outage, customers out above the customer total): no patient's power "returns" for one interval, and no fraction exceeds 1. (Task S1)
3. A caller gives no number, a garbled number, or says nothing: no backup value changes without a confirmed read-back, and silence escalates. (Tasks V1, V2)
4. A dispatcher rejects a proposal or never answers: no call, no text, and the patient's state is unchanged. (Tasks 5, 7)
5. The model returns invalid JSON, errors or times out: the interpreter retries once then returns `wants_human`; a survey ends with a `done` trace event carrying the error and a default-backed profile. (Tasks 4, V1)

Formula (heuristic, coefficients in `assumptions.yaml` under `building.tc`): `heat_h = default_heat_tc_h * construction * roof * shade * age`, clamped to 3..24. `construction`: masonry 1.3, concrete 1.3, steel 1.0, wood 0.9, unknown 1.0. `roof`: light 1.15, medium 1.0, dark 0.85. `shade = 1 + 0.3 * tree_cover_fraction`. `age`: before 1980 0.9, 1980-1999 1.0, 2000 on 1.15. `cold_h` uses `default_cold_tc_h` with construction and age only. `service_minutes = service_base_min + service_min_per_floor_no_elevator * patient_floor` when the elevator is not working or `elevator_count.value == 0`, else `service_base_min`.

```python
def outside_dark_area(lat:float, lon:float, dark_zips:set[str]) -> bool
def eligible(option_profile:BuildingProfile, patient:Patient) -> tuple[bool, list[str]]   # reasons either way
def propose(patient:Patient, dark_zips:set[str]) -> Iterator[TraceEvent]     # ends at kind="interrupt", data={"proposal_id":...}
def decide(proposal_id:str, decision:Literal["approve","reject"], reason:str|None) -> RefugeProposal
```

`eligible` is code, not model: a wheelchair or bedbound patient needs `step_free_entrance.value is True`, and `elevator_count.value >= 1` if the refuge has more than one floor; unknown values make the option ineligible with the reason "unverified access". The refuge agent is a second `create_deep_agent` with `memory=[MEMORY_FILE]` and `interrupt_on={"submit_proposal": True}`; it searches hotels and senior housing, surveys each candidate (cache first), filters with `eligible`, ranks, and calls `submit_proposal`. `decide("reject", reason)` appends `- <date>: rejected <name>: <reason>` to `MEMORY_FILE`, sets status `rejected`, and resumes the thread with a reject decision. `decide("approve")` sets status `approved` and resumes. Nothing else in the codebase may contact a patient about a move unless the proposal's status is `approved`.

### Task V2: Call logic and the custom-model endpoint

**Files:** Create `hearth/messaging/voice.py`, `hearth/messaging/scripts.py`; route added by lane M in `api/main.py` calling `voice.respond`. Test: `tests/messaging/test_voice.py`.

**Interfaces:**
- Consumes: V1, `store`.
- Produces:

```python
def start_call(patient_id:str, kind:Literal["impact","move_consent"], proposal_id:str|None=None) -> str   # call_id; stores a "call" doc
def respond(call_id:str, caller_text:str, keypad:str|None=None) -> str      # the agent's next line; updates the call doc
def confirmed_facts(call_id:str) -> dict                                     # only values the caller confirmed after read-back
```

`POST /voice/v1/chat/completions` is an OpenAI-compatible streaming endpoint that ElevenLabs calls as its model: it takes the last user message as `caller_text`, finds `call_id` in the request's extra body, and streams back `respond(...)`. A request with no `call_id` is an inbound call: start an `impact` call for the patient whose `phone` matches the caller's number, or answer `human_handoff` if none matches. `respond` is a state machine per call kind (`scripts.py`): `open -> ask -> readback -> temperature -> close` for `impact`; `open -> move_offer -> consent_readback -> close` for `move_consent`. Rules: a `backup_hours` value is stored only after the caller confirms the read-back; a later vague turn never overwrites a confirmed fact; `medical_question` returns `medical_handoff`; `wants_human` or confidence below 0.7 returns `human_handoff`; three empty turns in a row end the call and write an `escalation` event; a model-written acknowledgment is prepended only if `guard.allows` it. ElevenLabs agent settings (created once by script `python -m hearth.messaging.voice setup`): turn timeout 1.2 s minimum silence, interruptions on, keypad input on.
